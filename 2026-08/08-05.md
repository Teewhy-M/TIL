오늘 Git 과 Github 사용법에 대해 학습을 했다. 추후 팀원과 협업 또는 개인 기록을 위해 내 PC에 있는 파일을 Github에 전송하는 방법을 배웠다.
전송방법은 4단계 또는 4개의 공간을 거쳐 전송이되고, 작업한 일부 또는 전체를 선택해서 add-commit-push 를 거쳐 전송이된다.
push를 하는 단계에서 노트북과 github간의 권한? 때문에 막히는 부분이 생겼지만, 옆자리 고수님 덕분에 ssh를 통해 보다 쉽게 해결할 수 있었다.

위 과정을 하면서 여러가지 명령어를 사용했다.
 - git clone: 저장소(repository) 전체를 내가 사용하는 PC 또는 laptop에 복사
 - git branch: 현재 어느 branch에 위치하고 있는지 확인
    * branch: 복사된 작업물 (작업물을 수정 또는 테스트할 때 많이 사용, 작업 후 merge를 통해 main과 합치거나 폐기됨)
 - git add: 파일을 staging 영역에 위치하게함 (-A: 모든 파일 이동)
 - git commit -m '메세지': staging 영역에 있는 파일을 commit을 통해 로컬 저장소로 이동 (메세지는 보통 날짜, 목적 등 간단한 요약 내용을 작성)
 - git push: 로컬 저장소에 있는 파일을 github와 같은 클라우드에 전송
 - git pull: 반대로 저장소에 있는 파일을 내 PC로 불러옴

### Git 핵심 개념 및 명령어

- **`git add .` 의 역할**: 새 파일 추가뿐만 아니라 **파일 삭제 및 이동 이력까지 한 번에 추적(Staging)**에 등록합니다.
- **로컬과 원격의 분리**: 내 PC(로컬)에서 파일을 옮기거나 삭제했더라도, `git add` $\rightarrow$ `git commit` $\rightarrow$ `git push` 과정을 거쳐야만 **GitHub(원격)에 최종 반영**됩니다.
- **파일 이동 동작 원리**: Git에서 파일 이동은 내부적으로 `기존 위치 파일 삭제` + `새 위치 파일 생성`으로 처리됩니다.

### Linux 경로 기호 및 `mv` 명령어

| 기호 | 이름 | 실제 경로 예시 | 설명 |
| :--- | :--- | :--- | :--- |
| **`~/`** | 홈 디렉토리 | `/home/계정명/` | 현재 로그인한 사용자의 기본 개인 폴더 |
| **`/`** | 루트 디렉토리 | `/` | 시스템 전체의 최상위 뿌리 폴더 |
| **`./`** | 현재 디렉토리 | 현재 위치 | 현재 터미널이 위치한 폴더 |
| **`../`** | 상위 디렉토리 | 한 단계 위 폴더 | 바로 위에 있는 폴더 |

> **💡 `mv` 명령어 주의사항**  
> 목적지로 지정한 폴더가 존재하지 않으면 **파일명 변경(Rename)**으로 동작합니다.  
> (예: `mv practice.py ~/TIL` 입력 시 `~/TIL` 폴더가 없으면 홈 폴더에 `TIL`이라는 이름의 파일로 생성됨)

### 3. GitHub 브랜치 상태 및 동기화 (Merge)

- **`n commits ahead`**: 기준 브랜치에 없는 **내 새 커밋이 n개 존재**하며, Merge할 준비가 된 상태입니다.
- **`m commits behind`**: 내가 작업하는 동안 **기준 브랜치에 m개의 새 커밋이 추가**된 상태입니다.

### `n ahead, m behind` 상태 해결 순서

```bash
# 1. 원격 저장소의 최신 정보 수신
git fetch origin

# 2. 기준 브랜치(origin/main)의 변경 사항을 내 브랜치에 병합
git merge origin/main

# 3. 충돌(Conflict) 발생 시 코드 수정 후 반영
git add .
git commit -m "Fix merge conflicts"
git push
